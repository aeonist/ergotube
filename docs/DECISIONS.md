# Решения по проекту

Название: **ErgoTube** (выбрано 2 ноября 2026; прежнее рабочее название — FreshTuber). Внутренний идентификатор `app.freshtuber` сохраняется, чтобы обновления ставились поверх уже установленного приложения.

## Текущий приоритет — согласованная переработка управления (2 ноября 2026)

Все ответы пользователя и порядок кнопок записаны в [UX-REVISION.md](UX-REVISION.md). План: один уровень радиальной навигации, портретная страница «Свободный видеокадр» с колонкой действий и замком без подписи, сразу раскрытое управление полного экрана, постоянные действия Shorts, эллиптическая калибровка и ускорение загрузки Shorts. Этот план заменяет прежние решения о двух одновременно видимых дугах и круговой калибровке для следующей реализации.

**2 ноября пользователь явно разрешил реализацию: «да, пиши код».** Первоначальный запрет снят; исправления идут перед этапом 6. Описания этапа 5 ниже — история существующей сборки. Дополнительных продуктовых вопросов сейчас нет; спорные компоновки согласованы для пробы на работающем варианте.

## Технические решения (принимаю сам)

- **Вход**: WebView на accounts.google.com (та же ссылка, что у кнопки «Войти» на youtube.com), потом m.youtube.com. Сначала обычный WebView, но без заголовка `X-Requested-With` (так входит Metrolist). Если Google покажет страницу «небезопасный браузер», приложение само переключается на вид мобильного Chrome: User-Agent без пометки `wv` и метаданные браузера (Client Hints) без бренда «Android WebView». Режим можно переключить и вручную в меню «⋮». Если не поможет и это, добавлю импорт cookies.txt.
- **После входа**: из WebView забираются cookies youtube.com и из конфига страницы VISITOR_DATA, DATASYNC_ID, SESSION_INDEX. Вход проверяется запросом `account/account_menu`, затем WebView очищается полностью. Так зашифрованная копия остаётся единственной, и браузер не «ротирует» cookies у нас за спиной.
- **Авторизация InnerTube**: как у веб-клиента YouTube (сверено с yt-dlp): `SAPISIDHASH`, `SAPISID1PHASH`, `SAPISID3PHASH`, при известном id сессии с суффиксом `_u`. Плюс `X-Goog-AuthUser`, `X-Origin`, `X-Goog-Visitor-Id`. Новые cookies из `Set-Cookie` и новый `visitorData` из ответов сохраняются сразу.
- **Несколько аккаунтов**: у каждого аккаунта Google свой набор cookies, переключение мгновенное. Каналы внутри одного аккаунта (бренд-аккаунты) переключаются заголовком `X-Goog-PageId` и `onBehalfOfUser`, список каналов берётся из `account/accounts_list`.
- **Выход**: удаляет аккаунт из зашифрованного файла и чистит cookies, хранилище и кэш WebView. Если это был последний аккаунт, удаляется и сам файл, и кэш картинок.
- **Тестовые ответы аккаунта** (`app/src/test/resources/innertube`) собраны по структурам из Metrolist и yt-dlp, потому что для настоящих нужен вход. Когда появятся реальные, заменю их, убрав личные данные.
- **Осторожный режим для основного аккаунта**: cookies уходят только на youtube.com и googlevideo.com. Запросы с аккаунтом отправляются только по действию пользователя: открыл ленту, поставил лайк, подписался. Видеопотоки по умолчанию грузятся без аккаунта, cookies добавляются только для видео с возрастным ограничением. Фоновые проверки (уведомления) идут анонимно через RSS каналов. Частые действия ограничены по скорости.
- **Хранение cookies**: собственный ключ AES-GCM в Android Keystore. `EncryptedSharedPreferences` из ТЗ не беру: библиотека `androidx.security:security-crypto` объявлена устаревшей, а защита от этого не хуже.
- **Резервная копия Android** для приложения выключена полностью, чтобы cookies не попали в облако или на другой телефон.
- **DI**: Hilt (проверяет граф зависимостей при сборке).
- **Сборка**: AGP 9.4.1, Kotlin 2.4.21, KSP 2.3.12, Gradle 9.8.2, compileSdk 37, targetSdk 37, minSdk 26. NewPipeExtractor v0.26.5.
- **Media3** закреплён на 1.10.1: в 1.11.1 есть баг со скрытием медиа-управления на Android 17 (Metrolist #4404). Пересмотрю на этапе 4.
- **Язык данных YouTube**: NewPipeExtractor читает YouTube только по-английски (`en-GB`, так задумано в экстракторе). Поэтому даты («8 лет назад») и числа («1 млн просмотров») приложение форматирует само на языке интерфейса, а не берёт готовый текст.
- **Формат ответов YouTube (ноябрь 2026)**: ленты, плейлисты, канал и похожие видео приходят как `lockupViewModel`, Shorts как `shortsLockupViewModel`, часть поиска ещё как `videoRenderer`. Комментарии разнесены по сущностям в `frameworkUpdates`. Разбор обходит весь ответ и узнаёт карточки по типу, а не по фиксированному пути: так он переживает перестановки. Тесты гоняются на настоящих ответах, снятых без аккаунта (`app/src/test/resources/innertube/*.json.gz`).
- **Действия с аккаунтом** (лайк, подписка, комментарий, ответ, лайк комментария, плейлисты) повторяют команды, которые YouTube сам кладёт в ответ страницы (`likeEndpoint`, `subscribeEndpoint` и т.д.), вместе с их скрытыми `params`. Если команды нет, используется запасной вариант из YouTube.js. Пути API сверены с YouTube.js.
- **Осторожный режим**: между действиями с аккаунтом не меньше 1,2 секунды и не больше 40 действий за 10 минут. Лайк и подписка применяются на экране сразу и откатываются, если YouTube их не принял.
- **Без входа**: главная YouTube для гостя пустая, поэтому там подборки NewPipeExtractor (музыка, игры, подкасты, фильмы, трансляции). Поиск идёт через NewPipeExtractor. Страница видео, комментарии, каналы, плейлисты и Shorts берутся через анонимный InnerTube: это так же анонимно, а разбор у всех экранов один.
- **Shorts**: лента `reel/reel_watch_sequence`. С аккаунтом она начинается от Shorts из твоей главной, без аккаунта от поиска `#shorts`. В обычных лентах Shorts скрыты (настройка `shorts_in_feeds`, по умолчанию выкл).
- **DeArrow**: запрос по первым 4 символам SHA-256 от id видео, сервер не узнаёт, какое видео смотрят. Берутся только замены, за которые сообщество не голосовало против.
- **Return YouTube Dislike**: на сервис уходит только id видео.
- **Плеер**: потоки берёт NewPipeExtractor v0.26.5 без PoToken (сейчас работает: клиент Android). Видео и аудио идут отдельными потоками и склеиваются в ExoPlayer (MergingMediaSource), прямые эфиры через HLS. Если YouTube начнёт требовать PoToken, перенесу реализацию NewPipe на WebView.
- **Скорость загрузки**: запросы к googlevideo оформлены как у NewPipe (POST, параметры `range` и `rn` в адресе), а видео качается кусками по 10 МБ, как в yt-dlp. На эмуляторе буфер растёт примерно в 4 раза быстрее воспроизведения.
- **Сломанные декодеры**: если аппаратный декодер падает (у эмулятора падают все), плеер исключает именно его и берёт следующий, обычно программный. Если и это не помогло, переходит на другой кодек, потом на качество ниже.
- **Фон**: MediaSessionService с уведомлением и управлением на экране блокировки. При сворачивании со страницы видео открывается окошко поверх приложений, закрытие окошка ставит на паузу.
- **Позиция просмотра** хранится в Room на телефоне и восстанавливается, если просмотрено больше 10 секунд и до конца осталось больше 15.
- **История аккаунта**: при начале просмотра (с входом) запрашивается `player` от имени аккаунта, и один раз дёргается его `videostatsPlaybackUrl`, как это делает youtube.com.
- **SponsorBlock**: по хэш-префиксу, автоматически пропускаются категории `sponsor`, `selfpromo`, `interaction`.
- **Возрастные ограничения**: сначала анонимно, при отказе один повтор с cookies аккаунта, только для этого запроса.
- **Уведомления**: WorkManager, периодическая задача, RSS-ленты каналов (`feeds/videos.xml`), без cookies.
- **Shorts-лента**: с аккаунтом через InnerTube, без аккаунта через Shorts-вкладки каналов из подписок.

## Этапы

1. Каркас: Gradle, зависимости, `NewPipe.init`, тема, навигация, заглушки экранов.
2. Вход в аккаунт, хранение cookies, SAPISIDHASH, несколько аккаунтов, выход.
3. Данные: лента, подписки, история, плейлисты, комментарии, поиск, Shorts, дизлайки, DeArrow.
4. Плеер: DASH, качество, скорость, PiP, фон, субтитры, SponsorBlock, свайпы яркости и громкости, автоповтор, таймер сна, вертикальный плеер Shorts.
5. Круговое меню: раскладка, жесты, калибровка, левая и правая рука.
6. Подписки без аккаунта и уведомления о новых видео. Импорт Takeout CSV и NewPipe JSON отложен как необязательная задача.
7. Полировка: настройки всех функций, ошибки, офлайн, протухшие cookies.
8. Скачивание видео и просмотр без интернета.


## Этап 5 и исправления после этапа 4 — 2 ноября 2026

- **Главная с аккаунтом**: отдельный `FeedParser.parseHome` читает основную `richGridRenderer` и append/reload-продолжения. Из `richItemRenderer.content` принимаются только карточки видео/плейлистов; редакционные полки, региональные новости, Shorts-полки, реклама и их собственные продолжения пропускаются. Другие ленты сохраняют общий разбор. Формат сверен с [YouTube.js HomeFeed](https://github.com/LuanRT/YouTube.js/blob/main/src/parser/youtube/HomeFeed.ts). Добавлен структурный обезличенный пример, настоящего ответа с аккаунтом в проекте пока нет.
- **Страна запросов**: `gl` уже берётся из двухбуквенной страны системной локали; если её нет — `US`. Страна не зафиксирована на России и не определяется по IP приложением. Язык `hl` берётся отдельно из языка локали. В этом этапе поведение страны не менялось.
- **Отступы плеера**: общий Scaffold не добавляет системные отступы странице видео, а обычным экранам передаёт их с `consumeWindowInsets`. Портретный плеер добавляет верхний отступ ровно один раз на чёрном фоне. Полный экран рисуется во всё окно, включая вырез; только кнопки учитывают безопасные зоны. Режим выреза и значки строки состояния восстанавливаются при выходе.
- **Плеер в шторке**: Activity подключает `MediaController` к `PlaybackService` в `onStart`, освобождает соединение в `onStop`. Это создаёт штатный notification controller Media3. В медиасессии — обложка, название, канал, системная полоса перемотки, пауза, встроенные команды ±10 секунд и отдельная команда следующего видео; она доступна, когда есть очередь. Проверено в шторке API 37. API сверены с [Media3 background playback](https://developer.android.com/media/media3/session/background-playback) и [исходниками версии 1.10.1](https://github.com/androidx/media/tree/1.10.1/libraries/session).
- **Круговое меню**: красная кнопка в нижнем углу, внутри дуга разделов, снаружи — пункты выбранного раздела. В основной дуге шесть разделов: главная, Shorts, подписки, поиск, библиотека, аккаунт. Настройки находятся во внешней дуге аккаунта. Библиотека открывает историю, плейлисты, «Смотреть позже» и понравившиеся; аккаунт — переключение сохранённых аккаунтов/каналов и добавление аккаунта. Фильтры главной публикует сам экран; они сохраняются, пока его ViewModel находится в стеке навигации, и доступны из других разделов. Выбор возвращает на главную и применяет фильтр. Кэш сбрасывается при смене аккаунта или его канала. Наведение не загружает аккаунтные ленты.
- **Жесты**: короткое нажатие раскрывает меню; нажатие раздела раскрывает его внешнюю дугу. Можно вести палец от якоря через раздел к пункту и отпустить для выбора. Наведение само по себе не выполняет действие. Отпускание в пустом месте отменяет выбор, системная кнопка «Назад» закрывает меню. Есть виброотклик при смене цели и подписи для TalkBack.
- **Размеры и калибровка**: внутренние цели 48 dp, внешние от 64 dp (растут вместе со шрифтом), якорь 56 dp. Геометрия рассчитывается от доступного окна с учётом системных жестов и выреза; при нехватке места пункты перелистываются. При крупном системном шрифте увеличиваются внешние кнопки и отступ от края, а не уменьшается текст. В совсем низком окне доступен список. Рука, радиус и размах дуги сохраняются в DataStore. Калибровка измеряет медианное расстояние дуги от настоящего положения якоря, игнорирует точки с другой стороны и слишком короткие жесты. Также есть ручной ползунок расстояния и сброс.
- **Управление видео**: пауза/воспроизведение и ±10 секунд находятся на дуге поверх видео; открытая дуга удерживает управление видимым и закрывается через 4 секунды без действий. Управление прогрессом, полный экран и настройки видео сохранены; кнопка следующего видео перенесена к верхним кнопкам, чтобы не пересекаться с якорем. При раскрытой дуге верхние кнопки скрываются. PiP работает без круговых кнопок.
- **Проверка**: `assembleDebug testDebugUnitTest`, 77 тестов без ошибок (новые: разбор главной, геометрия для узких окон, зеркальность рук, выбор целей, калибровка и повреждённые значения настроек). Эмулятор API 37: выбор «Игры» одним движением, правая/левая рука, светлая тема со шрифтом 1,3, сохранение дуги после перезапуска, видео, шторка, альбомный экран с имитацией выреза. Эмулятор проверен без аккаунта. Файл для установки: `apk/FreshTuber-stage5-debug.apk`.

Следующий этап — **6: локальные подписки и анонимные RSS-уведомления**. Полный набор переключателей настроек остаётся этапом 7, скачивание — этапом 8.

- **Финальная проверка интерфейса этапа 5**: независимый обзор нашёл три замечания (фильтры главной из других экранов, пересечение кнопок вертикального плеера, переносы подписей). Внешний вид и токены записаны в `DESIGN.md` и `.impeccable/design.json`.

## Переработка управления после этапа 5 — 2 ноября 2026

- Навигация показывает один уровень с иконками и подписями. Раздел заменяется своими функциями, «Назад» возвращает на предыдущий уровень. Нет второй одновременно видимой дуги или дублирующего родителя. Текущее местоположение обозначено обводкой, цель жеста — заливкой. Аккаунты и каналы разнесены по отдельным уровням. Длинная подпись понравившихся в меню сокращена до «Любимые»; полное название сохранено для доступности.
- Портретная страница следует выбранному варианту «Свободный видеокадр»: видеокадр во всю ширину; колонка ниже него. Снизу вверх: «Ещё», полный экран, лайк, дизлайк, комментарии, подписка. При прокрутке колонка уезжает к краю рабочей руки, нижнее содержимое получает всю ширину; полный экран остаётся в нижней панели. Красная навигационная кнопка и замок находятся внизу вне видеокадра.
